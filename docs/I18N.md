# Internationalization

Every text a player can see is a translation key. English (`en_us.json`) is the source language; other
languages (or a translation API pipeline) are generated from it later.

## Rules (enforced)
- Use `Tr.tr("key", args...)`. Never `Component.literal(...)` outside `i18n/` (`no-literal-text` rule).
- Every key used in code must exist in `src/main/resources/assets/skyatlaz/lang/en_us.json`
  (`TranslationKeysTest`). Keys are passed as plain string literals so the test can find them.
- Dynamic values (numbers, player names, item names from the server) go in as **arguments**, never by
  concatenating strings: `tr("slayer.xp.gained", xp)` with `"%s XP gained"`.

## Key naming
`skyatlaz.<area>.<feature>.<element>` - `Tr` adds the `skyatlaz.` prefix.
```
skyatlaz.config.dungeons.score_hud.name
skyatlaz.config.dungeons.score_hud.description
skyatlaz.dungeons.score_hud.title
skyatlaz.error.module_disabled
```
- Lowercase, `snake_case` segments, dot separated.
- Config entries always have `.name` and `.description`.
- Keep keys sorted by area inside `en_us.json`.

## Adding a language
Copy `en_us.json` to `<locale>.json` (e.g. `es_es.json`) and translate values only. Missing keys fall back to English.
